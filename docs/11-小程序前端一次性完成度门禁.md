# 11-小程序前端一次性完成度门禁

本文件由 `C:\Obsidian\小程序复刻相关\社区团购小程序前端标准化复刻案例\M4-小程序前端一次性完成度门禁.md` 迁移改写而来。

本门禁是页面实现和验收门禁，不是登录鉴权门禁。目标是让“校园拾喵驿站 / 校园流浪猫驿站系统”的微信小程序页面在开发前先锁定参考图、素材、布局、安全区和验收边界，减少反复猜图、猜尺寸、猜素材。

## 适用范围

以下场景必须先读本文件：

- 新实现或重做任意小程序页面。
- 根据 `效果图/` 或用户截图复刻页面视觉。
- 接入 Banner、背景、猫咪照片、吉祥物、图标等本地素材。
- 修复图片比例、横幅裁切、卡片间距、文字溢出、底部输入栏、安全区等视觉问题。
- 修改 `pages/home/`、`pages/cats/`、`pages/help/`、`pages/mine/` 等同学端页面结构。

以下场景不适用：

- 后端 API 实现。
- 数据库 SQL 编写。
- Vue 后台管理页面。
- 真实微信授权、支付、地图、线上部署。

## 一句话原则

先锁参考、素材、数据状态和验收口径，再写 WXML / WXSS / JavaScript。

不要一边找图一边写代码；不要先写页面再补素材语义；不要把静态 mock 预览写成真实后端验收通过。

## Codex 职责边界

- Codex 不负责生图，也不得声称参与外部生图。
- Codex 负责接收素材、读取素材说明、体检素材、建立素材映射、把合格运行素材接入小程序、实现页面结构和静态检查。
- 如果素材不适合接入，应输出 STOP 结论和证据，不得继续用 WXSS 硬凑。

## 页面专属素材包权威规则

页面级复刻时，素材源优先级必须是：

1. 当前页面专属已解压素材包。
2. 当前页面专属素材包中的 `manifest`、`README`、`pixel spec`。
3. 当前页面专属素材包压缩包。
4. 用户当前明确指定的截图或效果图。
5. 通用处理版素材。
6. 原始效果图 fallback。

只有当前一层明确不存在、无法读取，或用户明确批准时，才允许进入下一层。不能把 fallback 当成默认行动；不能在未检查页面专属素材包的情况下直接使用效果图 fallback。

## 路径相对化规则

- 文档、prompt、AGENTS、门禁、复盘、操作日志和最终报告中不得新增本机绝对路径。
- 用户给出的本机路径只能作为外部上下文，写入规则时必须转译成路径角色，例如“当前工作区根”“小程序源码根”“页面专属素材包”“`docs/`”“`static/home/`”。
- 小程序运行时图片路径不得引用资料目录，只能使用小程序内运行路径或接口返回路径。

## 素材源 fallback 审批规则

- fallback 是受控例外，不是默认动作。
- 进入下一层 fallback 前，必须记录上一层的检查结果：未找到、不可读、尺寸不匹配、缺少目标文件，或用户明确批准。
- 需要 fallback 到原始效果图时，必须先说明风险并等待用户确认。
- prompt 中出现的候选路径不能机械执行；用户当前明确上下文优先于旧 prompt fallback。

## 外部素材接入前检查

接入外部处理好的素材前，必须先检查：

- 是否有 `README`、`manifest`、`pixel spec` 或素材说明。
- 图片尺寸、格式、色彩模式、是否有 alpha 通道。
- 透明素材的非透明 bbox、可见主体比例和四周透明留白。
- 吉祥物、头像、图标是否有矩形底、伪透明底、棋盘格或多余白边。
- 背景图是否错误包含表单、按钮、动态文案、系统 UI 或手机外框。
- 猫咪照片、头像、缩略图是否被错误透明化。
- 图标是否应来自统一 icon sheet、全局图标集或页面专属图标集。

检查失败时必须 STOP；不得用 `margin`、`transform`、`scale`、`z-index` 长时间硬凑错误素材。

## 动态字段与固定素材边界

- 固定横幅可以保留不可变文案，但搜索框、输入框、按钮、列表标题、用户昵称、状态、时间、地点、评论内容等动态字段不得固化进图片。
- 可变头像、猫咪缩略图、上传图片必须作为独立图片字段接入，不得嵌在卡片背景里。
- WXML 中的图片路径应集中来自页面数据对象、mock 数据或接口返回字段，不得到处散落硬编码。
- 接口字段未接入前可以使用 mock，但 mock 数据结构必须能平滑替换为接口数据。

## 裁剪前置校验

任何裁剪动作前必须完成：

- 确认源图来自权威素材源。
- 记录源图相对路径。
- 记录源图实际尺寸。
- 记录裁剪区域来源。
- 输出裁剪尺寸或预览结论。
- 源图尺寸与裁剪参数不匹配时立即停止。
- 裁剪框来自假设而不是标注时立即停止并要求用户确认。
- 禁止直接对效果图 fallback 裁剪，除非用户明确批准。

## 视觉复刻失败升级

同一页面同一视觉区域连续两轮 WXML/WXSS 调整仍不接近参考图时，不允许继续盲调：

- 停止局部 `margin`、`font-size`、`transform` 调整。
- 复盘差异类型：素材偏差、裁剪偏差、布局偏差、字体偏差、平台渲染偏差。
- 判断是否需要模块级素材、重新裁剪、重新选择素材源或补充几何记录。
- 若使用模块级素材，必须从权威素材源生成或裁剪。
- 必须写入页面几何记录和素材映射。

## Stop-the-line 停止条件

出现以下任一情况必须停止，不允许自作主张继续：

- 找不到页面专属素材包。
- 找不到任务依赖的素材包 `manifest`、`README` 或 `pixel spec`。
- 发现多个候选素材源，无法确定权威来源。
- 源图尺寸与裁剪参数不匹配。
- 需要 fallback 到效果图但用户没有授权。
- 需要写入本机绝对路径。
- 需要修改超出本轮允许范围的文件。
- 视觉验收必须依赖微信开发者工具截图，但当前没有执行截图验证。

## 页面几何记录强制项

高精度复刻、像素级复刻、截图还原、裁剪图接入时，必须在页面几何记录中至少记录：

- 参考来源。
- 目标视口宽度。
- 页面是否包含微信系统 UI。
- 关键区域顺序。
- 素材映射。
- 源图尺寸。
- 裁剪框来源。
- 裁剪输出尺寸。
- 未执行的截图、diff、真机验收。

轻量页面可以简化 bbox 表，但不能省略参考来源、素材映射和未验证项。

## 交付结论诚实性

- 静态检查通过只能写成静态检查通过，不能写成视觉通过。
- 未打开微信开发者工具，不能写 DevTools 预览通过。
- 未做真机截图，不能写真机通过。
- mock 数据展示不能写成数据库真实落库通过。
- 本地小程序能跑不能写成可上线。

## 写代码前最小工作流

1. 锁定本次只改哪个页面，写明页面路径。
2. 锁定参考来源：`效果图/`、用户截图、`首页素材/` 或 `校园拾喵驿站_素材处理版/`。
3. 锁定目标小程序源码根目录。
4. 列出页面所需数据字段，并对齐 `docs/04-接口契约.md` 与 `docs/05-小程序页面规格.md`。
5. 列出素材映射表，明确源路径、目标路径、图片用途、是否允许裁剪。
6. 判断页面使用微信默认导航栏还是自定义安全导航。
7. 判断每张图片使用 `aspectFill`、`aspectFit`、`widthFix` 还是固定比例容器。
8. 写 WXML / WXSS / JavaScript。
9. 做静态自检，最后再做微信开发者工具或真机验收。

## 页面实现前必须确认

| 检查项 | 必须确认 |
|---|---|
| 页面边界 | 本次只改哪些页面，哪些页面不改 |
| 页面路由 | 路由已在 `app.json` 声明 |
| 数据来源 | 页面通过 `utils/request.js` 或后端 API 获取数据，不直接散落写死数据 |
| mock 边界 | mock 只用于当前 UI 预览，不能冒充数据库真实数据 |
| 接口字段 | 字段名与 `docs/04-接口契约.md`、`utils/mockData.js` 保持一致 |
| 页面规格 | 行为变化已同步 `docs/05-小程序页面规格.md` |
| 素材来源 | 不修改 `素材/`、`效果图/`、`校园拾喵驿站_素材处理版/` 原始文件 |
| 素材目标 | 小程序运行素材复制到 `miniprogram/static/` 下 |
| 图片模式 | 每张图片的显示模式和容器比例已确认 |
| 导航栏 | 默认使用微信原生导航栏，不手动画状态栏、胶囊、系统时间 |
| 底部安全区 | TabBar、底部输入栏、发布按钮兼容 `env(safe-area-inset-bottom)` |
| 验收口径 | 明确 DevTools、真机、截图、自动化检查哪些已执行，哪些未执行 |

## 登录注册素材专项检查

- 背景图只能是氛围背景，不得包含表单卡片、输入框、按钮、标题文案。
- 吉祥物必须是真透明 PNG；必须检查 alpha 通道和非透明 bbox。
- 吉祥物可见主体比例过小、透明画布过大、边缘带矩形底时，先停止并修复运行素材，不得直接调大容器硬凑。
- 吉祥物与表单卡片重叠时，必须明确层级：谁遮住谁、是否会压住标题、输入框或按钮。

## 素材映射表模板

开发前至少填写以下内容，可写入本文件下方、本轮操作日志或对应页面实现说明中。

| 页面区域 | 正确素材文件 | 素材类型 | 是否允许裁剪 | 是否允许透明化 | 是否必须保留文字 | 小程序目标路径 | 备注 |
|---|---|---|---|---|---|---|---|
| 首页顶部轮播 |  | 完整横幅 | 否 | 否 | 是 | `/static/home/` 或 `/static/banner/` | 带文字和按钮的横幅不要拆成背景 |
| 首页快捷入口 |  | 图标 | 可裁外白边 | 可 | 否 | `/static/home/` 或 `/static/icons/` | 不用于 TabBar 时可用 PNG/SVG |
| 猫咪图鉴卡片 |  | 猫咪照片 | 不裁主体 | 否 | 否 | `/static/cats/` | 头像、缩略图、详情大图分清 |
| 求助领养列表 |  | 配图或 Banner | 不裁主体 | 否 | 视图片而定 | `/static/banner/`、`/static/cats/` | 保持卡片比例稳定 |
| 登录注册 |  | 背景/吉祥物 | 不裁主体 | 否 | 否 | `/static/bg/`、`/static/mascot/` | 避免压住输入框 |
| TabBar |  | PNG 图标 | 可裁外白边 | 可 | 否 | `/static/icons/` | `app.json` TabBar 不优先用 SVG |

最低门槛是三列：是否允许裁剪、是否允许透明化、是否必须保留文字。

## 图片显示规则

| 图片类型 | 默认策略 |
|---|---|
| 完整横幅 | 用固定比例容器，优先 `aspectFill`；如果横幅内文字被裁，改用 `aspectFit` 或调整容器比例 |
| 页面背景 | 可铺满，但不得让内容和系统导航冲突 |
| 猫咪照片 | 卡片缩略图可 `aspectFill`，详情大图不能裁掉主体 |
| 吉祥物 | 优先 `aspectFit`，避免被容器裁切 |
| 图标 | 优先 `aspectFit`，图标容器尺寸固定 |
| 用户上传图 | 列表缩略图可裁切，详情图尽量保留主体 |

禁止：

- 把完整横幅当普通背景图再叠一遍同样文字。
- 把分类/入口图标误用成猫咪照片或求助配图。
- 把带文字、按钮、插画的完整卡片做透明化。
- 用 Obsidian 资料目录的绝对路径作为小程序运行时图片路径。

## 微信小程序对齐规则

- 精确对齐时，`image` 必须放在固定尺寸容器中，并显式设置 `width`、`height`、`display: block` 和合适的 `mode`。
- 图标与文字横排时，使用 `flex`、固定 icon-box、文本容器和稳定 `line-height`；不要依赖 `text` 默认 inline 行为。
- 需要多行文本时，文本容器负责换行和高度，不能用单个文字的 `margin-left`、`position:absolute` 或 `transform` 硬调。
- 背景层、装饰层、内容层、遮挡层必须明确 `z-index` 关系；层级错误时先修层级，不继续调间距。
- TabBar 只允许使用全局统一实现；图标尺寸、文字样式、选中态和跳转方式必须在全局统一，不在单页局部修。

## 微信系统 UI 与安全区规则

当前项目默认使用微信小程序原生导航栏：

- 不手动画 `9:41`、信号、电量、Wi-Fi。
- 不手动画微信右上角胶囊、圆点菜单。
- 页面 `json` 使用 `navigationBarTitleText`、`navigationBarBackgroundColor`、`navigationBarTextStyle`。
- 只有用户明确要求自定义导航，才引入统一 `safe-nav` 组件。

如果后续确实启用自定义导航，必须统一实现安全区计算，不允许每页手写固定顶部高度：

```js
function getLayoutMetrics() {
  const win = wx.getWindowInfo ? wx.getWindowInfo() : wx.getSystemInfoSync()
  const menu = wx.getMenuButtonBoundingClientRect()
  const statusBarPx = win.statusBarHeight || 0
  const capsuleTopPx = menu.top || statusBarPx
  const capsuleHeightPx = menu.height || 32
  const capsuleBottomPx = menu.bottom || capsuleTopPx + capsuleHeightPx
  const navGapPx = Math.max(capsuleTopPx - statusBarPx, 0)
  const safeNavPx = capsuleBottomPx + navGapPx
  const bottomSafePx = win.safeArea ? Math.max(win.screenHeight - win.safeArea.bottom, 0) : 0
  const pxToRpx = (px) => px * 750 / win.windowWidth

  return {
    statusBarPx,
    safeNavPx,
    bottomSafePx,
    safeNavRpx: pxToRpx(safeNavPx),
    bottomSafeRpx: pxToRpx(bottomSafePx)
  }
}
```

## 视觉复刻增强门禁

当用户要求“尽量贴近效果图”“按截图重做”“复刻某页面”时，开发前至少做一个轻量几何记录。

建议在当前项目下创建：

```text
docs/ui-geometry-contracts/<page-name>/
  source-meta.json
  asset-map.csv
  layout-notes.md
```

简单页面可以不做完整 bbox 表，但必须记录：

- 参考图文件路径或截图来源。
- 目标视口宽度。
- 页面是否包含微信系统 UI。
- 关键区域顺序：顶部区、主内容区、列表区、底部固定区。
- 主图、卡片、按钮、输入栏的目标比例和间距。
- 素材映射。
- 当前未执行的截图/diff/真机验收。

复杂页面或高精度复刻页面再补：

```text
bbox-table.csv
constraints.csv
implementation-plan.md
```

## 页面级路径约束

图片路径优先集中在页面数据对象、mock 数据或接口返回数据里。

推荐：

```js
data: {
  assets: {
    banner: "/static/home/banner_home_rescue_hero.png",
    emptyCat: "/static/mascot/mascot_default_avatar.png"
  }
}
```

WXML 使用：

```xml
<image src="{{assets.banner}}" mode="aspectFill" />
```

不要在多个 WXML、JS、WXSS 文件里散落同一素材路径。

## 开发后硬检查

每次改小程序页面后，至少检查：

- `app.json` 是合法 JSON。
- 相关页面 `.js/.json/.wxml/.wxss` 都存在。
- `app.json` 中页面路径没有失效。
- TabBar 图标文件存在。
- 页面引用的 `/static/` 图片文件存在。
- 源码中没有 `C:\Obsidian` 绝对路径。
- 没有复制 `source_originals_renamed`、`preview_*.jpg`、`素材.zip` 或原始批次目录到小程序 `static/`。
- 登录拦截页面无 token 时能跳登录页。
- 底部输入栏、底部按钮和 TabBar 不互相遮挡。
- 结论区分已通过、已失败、未执行、当前环境无法验证。

## 交付结论模板

```text
已完成：
已验证：
未验证：
未执行：
当前环境无法确认：
仍有风险：
```

禁止把以下内容写成已通过：

- 未打开微信开发者工具，却写“DevTools 预览通过”。
- 只做 JSON/路径检查，却写“视觉验收通过”。
- mock 数据展示成功，却写“数据库真实落库通过”。
- 本地小程序能跑，却写“生产可上线”。

## 本项目禁止迁入的源项目内容

从 `C:\Obsidian\小程序复刻相关` 迁移本门禁时，只借鉴前端复刻流程，不迁入以下内容：

- 社区团购业务规则。
- 商品、购物车、订单、优惠券、支付、配送、自提点业务。

- 先锁参考图和素材再写页面。
- 完整横幅不拆、不透明化、不二次叠同文案。

- 操作日志和 checkpoint 必须保留已通过、已失败、未执行、当前环境无法验证。
