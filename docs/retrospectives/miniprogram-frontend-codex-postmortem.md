# 小程序前端实现 Codex 复盘

## Codex 实际参与了什么

- 读取项目规则、页面规格、素材规范和前端门禁。
- 根据用户提供的页面效果图和已处理素材包，实现多个微信小程序页面。
- 将页面运行素材接入小程序 `static/` 目录。
- 编写或调整 WXML、WXSS、JS、mock 数据和部分几何记录。
- 做静态检查：JSON、JS 语法、图片路径、素材是否存在、alpha 通道、旧素材目录引用等。
- 根据用户截图反馈，多次调整页面布局、图片层级、图标尺寸和 TabBar 方案。
- 在最终回复中汇报已完成、已验证、未验证、未执行和风险。

## Codex 没参与什么

- 没有参与外部生图过程。
- 没有决定原始效果图如何生成。
- 没有负责真实微信授权、真实登录注册、后端接口联调、数据库落库或线上部署。
- 没有完成 DevTools 截图 diff 或真机验收，除非后续明确执行并留下证据。

## 暴露的问题

### 1. 素材源和路径发现不够坚决

问题：
在页面复刻时，曾经没有把页面专属素材包作为最高优先级来源，也曾被 prompt 中的候选路径牵着走。

根因：
没有把“先发现权威素材包、再行动”当成硬闸门，容易把 fallback 当作执行清单。

应该 STOP 的情况：
- 未列出页面专属素材包文件清单。
- 未读取素材包 `README` 或 `manifest`。
- 出现多个候选素材源但权威来源不清。
- 需要从效果图 fallback，但用户没有明确批准。

### 2. 素材体检不足

问题：
有些 PNG 虽然有 alpha 通道，但透明画布过大、可见 bbox 太小，直接接入后会导致图标或吉祥物缩小、偏移或遮挡。

根因：
把“有透明通道”误当成“可直接接入”，没有检查非透明 bbox、主体占比、边缘底色和真实可视区域。

应该 STOP 的情况：
- 吉祥物、头像、图标的非透明 bbox 明显不适合目标容器。
- 透明素材带矩形底、伪透明底或过大留白。
- 背景图包含表单、按钮、标题、输入框等动态 UI。
- 猫咪照片或头像被错误透明化。

### 3. 用 WXSS 硬凑素材问题

问题：
在素材本身留白、裁切或层级不合适时，曾继续调整 `margin`、字号、尺寸、`z-index`，导致问题反复出现。

根因：
没有及时区分素材问题和布局问题；两轮样式调整失败后没有立即升级为复盘和素材体检。

应该 STOP 的情况：
- 同一视觉区域连续两轮调整仍明显不像效果图。
- 单点 `margin`、`transform`、`position` 只能修一个截图，无法解释通用规律。
- 调整后出现新的遮挡、错位或比例异常。

### 4. 动态内容与整图边界混乱

问题：
为了贴近效果图，部分区域曾倾向于用截图模块或固定图片解决，但页面里有些文字、状态、头像、时间、地点和评论应保持动态。

根因：
没有在实现前明确“固定横幅”和“动态字段”的边界。

应该 STOP 的情况：
- 搜索框、输入框、按钮、用户昵称、状态、日期、地点、评论内容被固化进图片。
- 后续接口字段无法替换 mock 数据。
- WXML 到处散落硬编码图片路径和业务文案。

### 5. TabBar 没有一开始全局统一

问题：
底部导航曾在不同页面里反复出现文字不齐、图标过小、局部修复互相打架。

根因：
把 TabBar 当作页面局部组件修，而不是全局导航系统。

应该 STOP 的情况：
- 多个主页面各自维护底栏结构和图标。
- 同一图标在不同页面使用不同素材或尺寸。
- Tab 页之间没有统一使用同一种跳转策略。

### 6. 小程序渲染细节没有前置锁定

问题：
`image`、`text`、`view` 默认渲染行为导致图文对齐、缩略图偏移、图标可见面积和表单层级多次出错。

根因：
没有在写页面前把固定容器、`display:block`、`line-height`、`aspectFill/aspectFit`、层级关系作为统一约束。

应该 STOP 的情况：
- 图标和文字只能靠单个 `margin-left` 对齐。
- 图片没有固定容器和明确 `mode`。
- 背景层、装饰层、内容层、遮挡层的 `z-index` 关系不清。

### 7. 验收汇报容易过度表达

问题：
静态检查通过、素材存在、JS 语法通过，不能等同于视觉复刻通过或真机通过。

根因：
最终汇报没有足够严格地区分静态检查、DevTools 截图、真机、后端联调。

应该 STOP 的情况：
- 用户要求视觉一致，但当前没有 DevTools 截图证据。
- 只做 mock 数据展示，却要声明接口或数据库通过。
- 只做文件存在检查，却要声明页面效果通过。

## 后续可复用规则

1. Codex 不负责生图，只负责素材接收、体检、接入、页面实现和验收边界汇报。
2. 页面实现前必须先读项目 AGENTS、前端门禁、素材规范、页面规格和页面专属素材说明。
3. 先发现小程序源码根、目标页面、可写范围、禁止范围、权威素材源，再写代码。
4. 外部素材进入 `static/` 前必须体检尺寸、格式、alpha、非透明 bbox、主体占比和是否混入动态 UI。
5. 素材不合格必须 STOP，不允许用 CSS 硬凑。
6. 动态数据不得固化进图片或 WXML 静态结构，必须保留后续接口替换能力。
7. 固定横幅、背景氛围、装饰图、头像、缩略图、图标、动态文案必须分层处理。
8. TabBar 必须全局统一，禁止在多个主页面各自手写和各自调样式。
9. 微信小程序精确对齐必须使用固定 icon-box、`display:block`、稳定 `line-height`、明确图片 `mode` 和清晰层级。
10. 同一区域两轮样式调整失败后必须停止复盘，判断素材、几何、层级或平台渲染问题。
11. 最终汇报必须区分静态检查、DevTools 截图、真机验证和后端联调。
12. 未执行的验证必须写未执行；当前环境无法确认的内容不得写成已通过。
